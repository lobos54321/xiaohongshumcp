## ❌ 为什么会出现500错误？

**原因**：已经登录了，但还在尝试获取二维码！

### 时间线
```
04:31:20 开始尝试获取二维码
04:31:20 🍪 加载Cookie: 3242 字节 (已登录状态)
04:31:21 🌐 访问登录页面
04:31:25 ✅ 登录页面加载完成
04:31:30 🔍 查找扫码登录按钮
04:31:30 ⚠️  未找到扫码登录按钮 (因为已登录)
04:32:00 ❌ 获取二维码元素失败: context deadline exceeded (30秒超时)
```

**小红书的行为**：
- 如果**未登录** → 显示二维码 ✅
- 如果**已登录** → 直接跳转到首页，不显示二维码 ✅

所以当已登录时，MCP Go等待30秒也找不到二维码元素，最终超时返回500错误。

## 🔍 前端错误："signal is aborted without reason"

```javascript
❌ [BackendAPI] Request Failed: {
  url: '...auto-login',
  method: 'POST',
  error: 'signal is aborted without reason'
}
```

**原因**：前端请求超时（30秒），在MCP Go超时（30秒）之前就abort了。

前端的timeout是30秒：
```typescript
private readonly timeout = 30000; // 30秒
```

但后端需要：
- 浏览器启动：5秒
- 页面加载：5秒
- 等待二维码：30秒
- **总计：40秒**

所以前端30秒超时太短了。

## ✅ 解决方案

### 方案1：检查登录状态（推荐）

**前端在点击"登录"按钮前先检查登录状态**：

```typescript
const handleAutoLogin = async () => {
  try {
    setChecking(true);
    
    // 🔥 先检查登录状态
    const status = await xiaohongshuAPI.checkLoginStatus(xhsUserId);
    if (status.isLoggedIn) {
      // 已登录，直接成功
      onLoginSuccess();
      return;
    }
    
    // 未登录，才获取二维码
    const response = await xiaohongshuAPI.autoLogin(xhsUserId);
    // ...
  }
}
```
