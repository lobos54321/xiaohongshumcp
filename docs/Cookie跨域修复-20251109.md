# Cookie跨域修复 - 解决新账号登录后发布失败问题

## 问题背景

**日期**: 2025-11-09
**问题描述**: 用户使用新的小红书账号扫码登录成功后，尝试发布内容时失败，导航超时并被重定向到登录页。

## 日志分析

### 错误日志
```
2025-11-08 12:18:17 - 🎉 [Cookie保存] ✅ 成功保存Cookie到文件!
Cookie数量: 12个，大小: 3239字节

2025-11-08 12:26:23 - ❌ [发布] 发布失败
导航到发布页面超时，卡在: https://creator.xiaohongshu.com/login?source=official&redirectReason=401
```

### 关键发现
- 登录成功，Cookie已保存（12个Cookie，3239字节）
- 发布时导航到 `creator.xiaohongshu.com` 被重定向到登录页
- 返回 `401` 错误码（Unauthorized - 未授权）
- `redirectReason=401` 表明认证失败

## 根本原因

### Cookie域名不匹配问题

1. **登录域名**: `www.xiaohongshu.com`
   - 文件: `xiaohongshu-mcp-build/xiaohongshu/login.go:98`
   - 代码: `pp.MustNavigate("https://www.xiaohongshu.com/login")`

2. **发布域名**: `creator.xiaohongshu.com`
   - 文件: `xiaohongshu-mcp-build/xiaohongshu/publish.go:32`
   - 代码: `urlOfPublic = "https://creator.xiaohongshu.com/publish/publish?source=official"`

3. **问题原因**:
   - 扫码登录在 `www.xiaohongshu.com` 完成
   - Cookie保存时只包含 `www` 子域名的会话信息
   - 当浏览器访问 `creator.xiaohongshu.com` 时，Cookie无法跨子域名使用
   - 导致 `creator` 子域名认为用户未登录，返回401错误

## 技术细节

### Cookie作用域

浏览器Cookie的域名作用域规则：
- Cookie设置为 `www.xiaohongshu.com` → 仅在 `www.xiaohongshu.com` 有效
- Cookie设置为 `.xiaohongshu.com` → 在所有 `*.xiaohongshu.com` 子域名有效

### 问题代码流程

**登录后Cookie保存流程** (service.go:142-158):
```go
if loginAction.WaitForLogin(ctxTimeout) {
    // 导航到首页
    page.Navigate("https://www.xiaohongshu.com/explore")
    page.MustWaitLoad()

    // 保存Cookie
    saveCookies(page)  // ← Cookie只在www域名有效
}
```

**发布时导航流程** (publish.go:61):
```go
pp.MustNavigate(urlOfPublic).MustWaitIdle().MustWaitDOMStable()
// urlOfPublic = "https://creator.xiaohongshu.com/publish/publish?source=official"
// ← 浏览器发现Cookie无效，重定向到登录页
```

## 解决方案

### 实施的修复

在QR扫码登录成功后，增加一个步骤：**访问creator域名建立会话**

**修改文件**: `xiaohongshu-mcp-build/service.go`

**修改位置**: 第154-173行（登录成功后，保存Cookie之前）

**修复代码**:
```go
// 🔥 FIX: 导航到creator域名建立会话，确保Cookie在creator子域名也有效
// 问题：登录在www.xiaohongshu.com，但发布在creator.xiaohongshu.com
// 解决：登录后访问creator域名，让浏览器在creator域名也建立有效会话
logrus.Info("🔄 [Cookie跨域] 导航到creator域名建立会话...")
if navErr := page.Navigate("https://creator.xiaohongshu.com"); navErr != nil {
    logrus.Warnf("⚠️ [Cookie跨域] 导航到creator域名失败: %v，可能影响后续发布", navErr)
} else {
    page.MustWaitLoad()
    // 等待2秒确保页面完全加载并建立会话
    time.Sleep(2 * time.Second)
    finalURL := page.MustInfo().URL
    logrus.Infof("✅ [Cookie跨域] Creator域名访问成功，当前URL: %s", finalURL)

    // 检查是否被重定向到登录页（说明Cookie跨域失败）
    if strings.Contains(finalURL, "/login") {
        logrus.Warnf("⚠️ [Cookie跨域] 访问creator域名被重定向到登录页，Cookie可能无法跨域使用")
    } else {
        logrus.Info("✅ [Cookie跨域] Creator域名会话建立成功，Cookie已在两个域名生效")
    }
}
```

### 修复流程

**新的登录流程**:
1. 用户扫码登录 (在 `www.xiaohongshu.com`)
2. 检测到登录成功
3. 导航到 `www.xiaohongshu.com/explore` （完成登录流程）✅
4. **【新增】** 导航到 `creator.xiaohongshu.com` （建立creator会话）✅
5. 保存Cookie（现在包含两个域名的会话）✅
6. 后续发布时访问 `creator.xiaohongshu.com` 成功 ✅

### 为什么这样修复有效

1. **会话建立**: 当浏览器访问 `creator.xiaohongshu.com` 时，服务器会识别到已登录状态（通过www的Cookie），并在creator域名也建立会话
2. **Cookie同步**: 浏览器会在两个子域名都保存有效的会话Cookie
3. **保存完整Cookie**: 调用 `saveCookies()` 时，保存的Cookie包含了两个域名的会话信息
4. **发布成功**: 后续发布时，浏览器加载Cookie后，在访问 `creator.xiaohongshu.com` 时有有效的会话

## 潜在风险与降级方案

### 潜在问题

1. **网络问题**: 如果导航到creator域名时网络失败，会记录警告但继续保存Cookie
2. **新账号限制**: 如果新账号没有creator权限，可能仍会被重定向到登录页
3. **Cookie策略变化**: 如果小红书修改Cookie跨域策略，可能需要调整方案

### 降级策略

代码中已包含降级处理：
- 如果导航creator失败，记录警告但不中断流程
- 仍然会保存www域名的Cookie
- 用户可以尝试手动在creator域名登录
