# 小红书自动化系统完整流程分析

## 目标
系统梳理从"扫码登录"到"发布内容"的完整链路，找出所有潜在问题。

## 1. 整体架构

```
用户浏览器 (前端)
    ↓
Claude Agent Service (Node.js - Port 8080)
    ↓
MCP Router (Node.js - Port 3000)
    ↓
MCP Go进程 (Go Binary - 动态端口如18060)
    ↓
Rod浏览器自动化 (Chromium)
    ↓
小红书网站
```

## 2. 核心流程拆解

### 流程A: 扫码登录获取Cookie

#### 前端触发
```typescript
文件: prome-platform/src/components/xiaohongshu/LoginSection.tsx
触发: 用户点击"登录"按钮
调用: xiaohongshuAPI.autoLogin(userId)
```

#### 后端处理
```typescript
文件: playwright-service/claude-agent-service/src/server.ts
端点: POST /agent/xiaohongshu/auto-login
流程:
  1. 检查现有Cookie是否有效
  2. 尝试MCP Router获取二维码
  3. 失败则降级到Playwright
  4. 再失败则尝试自动检测浏览器Cookie
```

#### MCP Router转发
```typescript
文件: playwright-service/mcp-router/src/httpServer.ts
端点: GET /api/xiaohongshu/login/qrcode?userId=xxx
流程:
  1. 为用户创建/获取MCP进程
  2. 创建Cookie符号链接
  3. 调用MCP Go进程的 /api/v1/login/qrcode
```

#### MCP Go执行
```go
文件: xiaohongshu-mcp-build/service.go
方法: GetLoginQrcode(ctx)
流程:
  1. 创建浏览器实例 (加载空Cookie)
  2. 调用 loginAction.FetchQrcodeImage(ctx)
  3. 在goroutine中等待扫码
  4. 扫码成功后调用 saveCookies(page)
```

#### 关键问题点
```
🔴 问题1: Cookie加载时机
- browser.go 在浏览器启动时加载Cookie
- 但此时Cookie文件是空的 []
- 影响：页面可能识别为"有Cookie但无效"

🔴 问题2: 二维码获取逻辑
文件: xiaohongshu-mcp-build/xiaohongshu/login.go
当前逻辑:
  - 访问 /login 页面
  - 等待2秒
  - 查找扫码按钮（3秒超时）
  - 等待二维码元素（30秒超时）

潜在问题:
  - 选择器可能不匹配
  - 页面加载可能需要更长时间
  - 小红书可能有反爬虫机制

🔴 问题3: 超时配置不一致
- claude-agent-service → MCP Router: 45秒
- MCP Router → MCP Go: 120秒
- MCP Go内部: 30秒
- 但实际只运行了8秒就失败了！
```

### 流程B: Cookie保存与持久化

#### Cookie保存时机
```go
文件: xiaohongshu-mcp-build/service.go:141
时机: 在goroutine中等待扫码成功后

代码:
go func() {
    if loginAction.WaitForLogin(ctxTimeout) {
        if er := saveCookies(page); er != nil {
            logrus.Errorf("failed to save cookies: %v", er)
        }
    }
}()
```

#### Cookie保存位置
```go
文件: xiaohongshu-mcp-build/service.go:453-466
方法: saveCookies(page *rod.Page)

流程:
1. page.Browser().GetCookies() - 从浏览器获取
2. json.Marshal(cks) - 序列化
3. cookieLoader.SaveCookies(data) - 保存到文件

保存路径由 cookies.GetCookiesFilePath() 决定
```

#### Cookie文件路径逻辑
```go
文件: xiaohongshu-mcp-build/cookies/cookies.go:48-66
方法: GetCookiesFilePath()

逻辑:
1. 检查 /tmp/cookies.json 是否存在 (旧路径)
2. 存在则使用旧路径
3. 否则使用环境变量 COOKIES_PATH
4. 默认 fallback 到 "cookies.json" (当前目录)

问题分析:
- MCP进程工作目录: /app/playwright-service/mcp-router/cookies/{userId}/
- 环境变量 COOKIES_PATH 没有设置
- 所以实际保存路径应该是: 当前目录/cookies.json
- 但符号链接指向: /app/data/cookies.json
```

#### 🔴 关键问题: Cookie路径混乱

```
实际执行情况:
1. ProcessManager创建符号链接:
   /app/data/cookies.json → /app/playwright-service/mcp-router/cookies/{userId}/cookies.json

2. MCP Go工作目录:
   /app/playwright-service/mcp-router/cookies/{userId}/

3. GetCookiesFilePath()返回:
   "cookies.json" (相对路径)

4. 实际读取位置:
   /app/playwright-service/mcp-router/cookies/{userId}/cookies.json ✅

5. 实际写入位置:
   /app/playwright-service/mcp-router/cookies/{userId}/cookies.json ✅

理论上路径是对的！但为什么Cookie还是空的？
```

## 3. 问题汇总

### 🔴 问题1: MCP Go获取二维码8秒失败

**现象**: 日志显示只运行了8秒就降级到Playwright

**可能原因**:
1. Rod浏览器初始化失败
2. 访问login页面失败（网络/反爬虫）
3. 页面元素选择器不匹配
4. Chromium路径问题

**验证方法**: 查看新增的详细日志

### 🔴 问题2: Cookie保存后仍然为空

**现象**: 日志显示Cookie大小2字节（只有`[]`）

**可能原因**:
1. saveCookies()在goroutine中，可能未执行
2. page.Browser().GetCookies()返回空数组
3. 文件写入失败但没报错
4. 扫码成功但WaitForLogin()未检测到

**验证方法**: 添加saveCookies详细日志

### 🔴 问题3: 超时时间不匹配

**配置汇总**:
| 层级 | 文件 | 超时时间 | 实际运行 |
|------|------|----------|----------|
| 前端 → 后端 | server.ts:1942 | 45秒 | ？ |
| 前端 → 后端 | server.ts:2564 | 45秒 | ？ |
| 后端 → MCP Router | processManager.ts:401 | 120秒 | ✅ |
| MCP Go内部 | login.go:89 | 30秒 | ❌ 8秒失败 |

**问题**: 为什么30秒超时但8秒就失败了？

### 🔴 问题4: 环境变量和路径配置

**需要检查的环境变量**:
- COOKIES_PATH: 未设置
- MCP_BINARY_PATH: 设置了吗？
- DISPLAY: :99 (Xvfb)
- CHROMIUM路径: /usr/bin/chromium (符号链接)
